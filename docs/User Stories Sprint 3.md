## **RF-005 \- Sistema de notificaciones por mail**

| Título: Notificación por cambios en el vuelo | Prioridad: Alta | Estimado: Medio |
| :---- | :---- | :---- |
| **Historia de usuario: US-025 Como** pasajero con pasaje confirmado **quiero** recibir un correo electrónico automático ante cambios de horario o cancelación de mi vuelo con el motivo y los canales de reprogramación **para** estar advertido inmediatamente de las contingencias operativas y evitar traslados innecesarios al aeropuerto. |  |  |
| **Criterios de aceptación: Criterio 1:** **Envío automático ante cancelación de vuelo**. **Dado** que un administrador confirma la cancelación de un vuelo programado desde la plataforma web  **Cuando** el sistema actualiza el estado operativo del vuelo  **Entonces** despacha automáticamente un correo electrónico a cada pasajero afectado con su código de reserva, número de vuelo, aviso explícito de cancelación y vías de contacto para reprogramación o reembolso. **Criterio 2:** **Envío automático ante reprogramación de horarios** **Dado** que un administrador modifica los horarios de partida o llegada de un vuelo con pasajes confirmados.  **Cuando** se guardan los cambios en el sistema.  **Entonces** envía automáticamente un email a las casillas registradas detallando el nuevo itinerario y el ajuste horario efectuado. **Criterio 3:** **Encolamiento y tolerancia a fallos SMTP. Dado** que se produce una interrupción transitoria en el servicio de correo electrónico  **Cuando** se generan eventos masivos de alerta de vuelo  **Entonces** el sistema encola las notificaciones en segundo plano y mantiene un registro histórico de envíos sin bloquear la continuidad operativa del backend.  |  |  |

**RF006 \- Reportes de ocupación (Prioridad)**

| Título: Reporte de ocupación | Prioridad: Alta | Estimado: Medio |
| :---- | :---- | :---- |
| **Historia de usuario: US \- 027 Como** administrador, **quiero** consultar un reporte de ocupación filtrando por vuelo, clase y rango de fechas, que muestre asientos vendidos, capacidad y porcentaje de ocupación,  **para** saber qué tan llenos están los vuelos y tomar decisiones comerciales. |  |  |
| Criterios de aceptación: **Criterio 1: Consulta y filtrado del reporte. Dado** que el administrador se encuentra en la pestaña “Reportes” **Cuando** selecciona vuelo, clase y/o rango de fechas y presiona “Aplicar” **Entonces** el sistema muestra únicamente las filas que cumplen con los filtros, cada una con asientos vendidos, capacidad y porcentaje de ocupación, y el botón “Limpiar” restablece la vista inicial.  **Criterio 2: Cálculo correcto de la ocupación. Dado** que un vuelo tiene pasajes en distintos estados **Cuando** el administrador consulta el reporte **Entonces** el sistema cuenta solo los pasajes confirmados y calcula la ocupación como vendidos ÷ capacidad × 100\.  **Criterio 3: Totales consolidados Dado** que el reporte muestra resultados **Cuando** el administrador aplica o cambia los filtros **Entonces** el sistema actualiza, sobre la tabla, el total de pasajes vendidos, la cantidad de vuelos incluidos y la ocupación promedio del resultado filtrado.  **Criterio 4: Filtros inválidos o sin resultados. Dado** que el administrador aplica filtros **Cuando** la fecha “Desde” es posterior a “Hasta” o no existen vuelos que cumplan los filtros **Entonces** el sistema no muestra la tabla y presenta un mensaje que indica el motivo.  |  |  |

**RF007 \- Aplicación Móvil**

| Título: Búsqueda de vuelos en app móvil | Prioridad: Alta | Estimado: Medio |
| :---- | :---- | :---- |
| **Historia de usuario: US-029 Como** pasajero desde mi celular, **quiero** buscar vuelos disponibles ingresando mi origen, destino y fecha, **para** consultar los horarios y precios en una interfaz adaptada a la pantalla de mi celular. |  |  |
| **Criterios de aceptación: Criterio 1: Búsqueda exitosa adaptada a móvil** **Dado** que el pasajero abre la aplicación móvil y se encuentra en la pantalla de inicio **Cuando** ingresa un origen, destino y fecha válidos en los selectores nativos y presiona “Buscar” **Entonces** el sistema devuelve una lista de vuelos disponibles, renderizando tarjetas optimizadas para pantallas chicas que discriminan claramente horarios, clases(Economy/Primera) y precios. **Criterio 2: Búsqueda sin resultados** **Dado** que el pasajero realiza una búsqueda de vuelos en la app **Cuando** no existen vuelos programados o con cupo para la fecha y ruta ingresada **Entonces** la aplicación muestra un mensaje amigable indicando que no hay vuelos disponibles e invita  al usuario a seleccionar fechas cercanas en el calendario móvil. |  |  |

| Título: Flujo de compra y reserva en aplicación móvil | Prioridad: Alta | Estimado: Alto |
| :---- | :---- | :---- |
| **Historia de usuario: US-030 Como** pasajero desde mi celular, **quiero** seleccionar un vuelo, cargar los datos de los pasajeros y completar el pago simulado, **para** adquirir mis pasajes íntegramente desde el celular sin depender de una computadora. |  |  |
| **Criterios de aceptación: Criterio 1: Completar reservas desde el celular** **Dado** que el pasajero seleccionó un vuelo específico desde los resultados de búsqueda móvil **Cuando** completa el formulario móvil con los datos de contacto, agrega a sus acompañantes (hasta 9 pasajes) y confirma el pago **Entonces** el backend procesa la transacción, bloquea los cupos de los asientos y la aplicación renderiza la pantalla de “Resumen de Reserva” confirmando la operación. **Criterio 2:** **Manejo de errores de conexión durante el pago Dado** que el pasajero se encuentra en el último paso del flujo de pago móvil  **Cuando** ocurre una pérdida de señal de internet (timeout) al presionar “Pagar” **Entonces** la aplicación intercepta el error, no bloquea la pantalla y muestra un aviso emergente solicitando verificar la conexión antes de reintentar la operación. |  |  |

**RF 008: Consulta y Almacenamiento Offline de Tickets Electrónicos**

| Título: Consulta offline de tickets electrónicos en app móvil  | Prioridad: Alto  | Estimado: Medio  |
| :---- | :---- | :---- |
| **Historia de usuario: US-032 Como** pasajero desde mi celular, **quiero** consultar y visualizar mis pasajes electrónicos previamente adquiridos aun cuando no tenga conexión a internet, **para** poder disponer de mi acreditación de viaje en cualquier momento durante el viaje, incluso en zonas sin conectividad.  |  |  |
| **Criterios de aceptación: Criterio 1: Consulta offline de un ticket almacenado Dado** que el pasajero adquirió un pasaje y este fue previamente sincronizado con la aplicación móvil**Cuando** abre la sección de “Mis pasajes” sin conexión a internet y selecciona el pasaje**Entonces** la aplicación permite visualizar íntegramente el ticket, incluyendo los datos esenciales del vuelo, pasajero y reserva, sin requerir conexión activa. **Criterio 2: Visualización del ticket sin conexión Dado** que el pasajero tiene un ticket almacenado localmente en el dispositivo**Cuando** activa el modo avión e ingresa a la aplicación**Entonces** el sistema permite abrir y renderizar correctamente el ticket almacenado, manteniendo disponibles los datos necesarios para su control o embarque. **Criterio 3: Sincronización al recuperar conectividad Dado** que el pasajero posee un ticket almacenado localmente y se restablece la conexión a internet**Cuando** la aplicación detecta nuevamente conectividad**Entonces** sincroniza automáticamente cualquier actualización disponible sobre el estado del vuelo y actualiza la información almacenada localmente. |  |  |

**Corrección de bugs previos**

| Título: Corrección de la política de cambios de estado de vuelo  | Prioridad: Alto  | Estimado: Medio  |
| :---- | :---- | :---- |
| **Historia de usuario: US-033 Como** administrador,  **quiero** que el sistema aplique la política completa de cambios de estado y de fechas de vuelo,  **para** que solo se permitan operaciones válidas y las reservas afectadas queden en un estado coherente.  |  |  |
| **Criterio 1 Dado** un vuelo CANCELADO, REPROGRAMADO u OPERADO,  **cuando** se intenta una operación,  **entonces** el sistema la rechaza con un mensaje que indica el estado terminal. **Criterio 2** **Dado** un vuelo ACTIVO,  **cuando** se registra una demora con hora posterior a la programada y anterior o igual a la salida vigente (+2 h si no despegó),  **entonces** el vuelo pasa a RETRASADO y la salida vigente se actualiza. **Criterio 3** **Dado** un vuelo RETRASADO,  **cuando** se registra una nueva demora,  **entonces** la nueva hora reemplaza a la anterior y no se acumula. **Criterio 4** **Dado** un vuelo ACTIVO o RETRASADO,  **cuando** se adelanta el horario dentro de la misma fecha de servicio,  **entonces** el vuelo pasa a ACTIVO o RETRASADO según corresponda y la salida vigente se actualiza. **Criterio 5** **Dado** un vuelo con salida vigente dentro de las próximas 48 horas,  **cuando** se intenta cambiar la fecha de servicio,  **entonces** el sistema lo rechaza y explica el límite. **Criterio 6 Dado** un vuelo con salida vigente y sin despegue registrado,  **cuando** pasaron más de 2 horas,  **entonces** el vuelo pasa a OPERADO y no admite cambios. **Criterio 7** **Dado** un cambio de horario,  **cuando** se confirma,  **entonces** las reservas conservan asiento y check-in y solo se notifica el cambio. |  |  |
